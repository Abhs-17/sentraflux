Project Overview

Sentraflux is a cloud-native security intelligence platform designed to analyze live web application traffic and provide actionable security insights for DevOps teams.

The system operates as an observability-driven security layer rather than a traditional blocking firewall. Instead of blocking requests in the request path, Sentraflux observes, learns, detects, and suggests.

How It Works

  1. Observes application traffic
  2. Learns normal behavior patterns
  3. Detects anomalies
  4. Generates security insights
  5. Suggests deployable WAF rules

This architecture allows security teams to adopt protection incrementally without risking production outages.

Section 03

System Architecture Overview

The system is divided into two major planes, each with distinct responsibilities and performance constraints.

Data Plane

Handles Live Traffic

  • HTTP reverse proxy
  • Traffic capture
  • Feature extraction
  • Telemetry emission

Latency impact must remain extremely low.

Control Plane

Handles Analytics

  • Anomaly detection
  • ML processing
  • Rule generation
  • Dashboards
  • Security analytics

Traffic signals are streamed asynchronously from the data plane to the control plane, decoupling performance-sensitive traffic handling from analytical workloads.

Service Structure

Gateway Service Go

Reverse proxy responsible for capturing HTTP traffic. Acts as the primary entry point into the Sentraflux data plane.

Proxy engine Request metadata capture Telemetry emission

Entry point: cmd/gateway/main.go

Feature Engine
services/feature-engine

Extracts security-relevant features from incoming requests for downstream analysis and anomaly detection.

Header entropy Path depth Query param structure User-agent fingerprinting
Telemetry Consumer
services/telemetry-consumer

Consumes events from the message stream and stores them for subsequent analysis.

Schema validation Event processing Storage integration

Machine learning–powered anomaly detection. Processes feature vectors from the feature engine to identify threats.

Dataset Management

Datasets are used to train anomaly detection models within the detection engine. The datasets/ directory is structured as follows: 

datasets/
├── raw/
├── processed/
└── synthetic-attacks/
⬛
Raw
Unprocessed captured traffic data
▪
Processed
Cleaned & feature-extracted datasets
◆
Synthetic Attacks
Adversarial training data

Synthetic Attack Datasets Include

  • Bot traffic
